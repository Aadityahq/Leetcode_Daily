# **LeetCode 3946 – Maximum Number of Items From Sale I**



Medium

Java



## **1. Understanding the problem**

You are given:

- `items[i][0]` → Factor of the item.
- `items[i][1]` → Price of the item.
- `budget` → Maximum money you can spend.

There are unlimited copies of every item.

The important rules are:

1. You can purchase multiple copies of any item.
2. If you purchase at least one copy of item `i`, you receive one free copy of every item `j` whose factor is divisible by the factor of item `i`.
3. You cannot receive a free copy of the same item from itself.
4. Buying multiple copies of the same item does not give additional free items.
5. Your goal is to maximize the total number of purchased and free items.

### **Example 1**

```
items = [[6,2],[2,6],[3,4]]
budget = 9
```

Let's understand the items:

| Item | Factor | Price |
| ---- | ------ | ----- |
| 0    | 6      | 2     |
| 1    | 2      | 6     |
| 2    | 3      | 4     |

Suppose we purchase:

- 2 copies of item 0 → Cost = 4
- 1 copy of item 2 → Cost = 4

Total spending = 8.

Now, because we purchased item 2, its factor is 3.

Since 3 divides 6, we receive one free copy of item 0.

**Final calculation**

| Type             | Copies |
| ---------------- | ------ |
| Purchased item 0 | 2      |
| Purchased item 2 | 1      |
| Free item 0      | 1      |
| **Total**        | **4**  |

# **4 items**

## **2. Important observation**

Instead of calculating free items every time we purchase something, we can precompute how many free items each item can generate.

For every item `i`:

\\[ free[i] = \text{number of items }j\ne i \\]

such that:

\\[ factor[j] \bmod factor[i] = 0 \\]

For example:

```
items = [[6,2],[2,6],[3,4]]
```

- Factor 6 divides 6 → 1 free item.
- Factor 2 divides 6 → 1 free item.
- Factor 3 divides 6 → 1 free item.

Therefore:

```
free = [0, 1, 1]
```

Notice that item 0 cannot generate a free copy of itself.

**Important:** Each purchased item type gives a fixed free-item bonus, regardless of how many copies we purchase.

## **3. Approach – Dynamic Programming (Unbounded Knapsack)**

We need to consider two possibilities for every item:

**Option 1: Don't purchase this item.**

- Cost = 0
- Additional items = 0

**Option 2: Purchase this item.**

- The first copy gives:
  - 1 purchased item.
  - `free[i]` free items.
- Every additional copy gives:
  - 1 purchased item.
  - No additional free items.

Therefore:

- First copy value = `1 + free[i]`
- Additional copy value = `1`

This is a variation of the Unbounded Knapsack problem.

The difference is that the first copy provides a bonus, while subsequent copies do not.

### **DP definition**

Let:

\\[ dp[b] = \text{maximum number of items using exactly }b\text{ money} \\]

Initially:

```
dp[0] = 0;
```

All other states are initialized to a very small value because they are initially unreachable.

For an item with price `p` and free bonus `w`, suppose we purchase `k` copies.

If `k = 0`, the additional value is 0.

If `k >= 1`, the additional value is:

\\[ w+k \\]

The transition is:

\\[ dp[b] = \max \begin{cases} dp[b] & \text{don't purchase this item}\\\ dp[b-kp]+w+k & k\geq 1 \end{cases} \\]

Here:

- `p` = item price.
- `w` = number of free items generated by this item.
- `k` = number of purchased copies.

A direct implementation would be too slow if we tried every possible `k` for every budget.

### **Optimization using prefix maximum**

We can optimize the transition to \\(O(n \times budget)\\).

For a fixed price `p`, divide budget positions into groups having the same remainder when divided by `p`.

For example, if `p = 3`, we process:

```
Group 0: 0, 3, 6, 9, 12 ...
Group 1: 1, 4, 7, 10, 13 ...
Group 2: 2, 5, 8, 11, 14 ...
```

Within each group, let:

\\[ t = \frac{b-r}{p} \\]

If we purchase `k` copies, the previous state is at position `t-k`.

Our transition becomes:

\\[ dp[b] = \max\left(prev[b], w+t+ \max\_{q\<t}(prev[r+qp]-q)\right) \\]

We maintain the maximum value inside the group while iterating.

This avoids checking every possible number of copies separately.

## **4. Calculating free items efficiently**

We also need to calculate `free[i]`.

Instead of comparing every item with every other item, use a frequency array.

Let:

```
freq[factor] = number of items having this factor
```

For each possible factor `d`, count all items whose factors are multiples of `d`.

```
for (int d = 1; d <= maxFactor; d++) {
    for (int multiple = d; multiple <= maxFactor; multiple += d) {
        count[d] += freq[multiple];
    }
}
```

Then:

```
free[i] = count[factor[i]] - 1;
```

We subtract 1 to exclude the item itself.

## **5. Java Solution**

```

class Solution {
    public int maxNumberSaleItems(int[][] items, int budget) {

        int n = items.length;
        int maxFactor = 1500;

        // Step 1: Count frequency of every factor
        int[] freq = new int[maxFactor + 1];

        for (int[] item : items) {
            freq[item[0]]++;
        }

        // Step 2: Calculate how many items each factor divides
        int[] count = new int[maxFactor + 1];

        for (int d = 1; d <= maxFactor; d++) {
            for (int multiple = d;
                 multiple <= maxFactor;
                 multiple += d) {

                count[d] += freq[multiple];
            }
        }

        // Step 3: DP initialization
        int NEG = -1_000_000;

        int[] dp = new int[budget + 1];
        java.util.Arrays.fill(dp, NEG);

        dp[0] = 0;

        // Step 4: Process every item
        for (int[] item : items) {

            int factor = item[0];
            int price = item[1];

            // Free items generated by this item
            int free = count[factor] - 1;

            // Preserve previous DP states
            int[] prev = dp.clone();

            // Step 5: Process each remainder group
            for (int r = 0; r < price && r <= budget; r++) {

                int best = NEG;

                int t = 0;

                for (int b = r; b <= budget; b += price) {

                    // Include previous position in prefix maximum
                    if (t > 0) {

                        int previous = prev[b - price];

                        if (previous != NEG) {
                            best = Math.max(
                                best,
                                previous - (t - 1)
                            );
                        }
                    }

                    // Option 1: Don't purchase this item
                    dp[b] = prev[b];

                    // Option 2: Purchase one or more copies
                    if (best != NEG) {

                        int candidate = free + t + best;

                        dp[b] = Math.max(
                            dp[b],
                            candidate
                        );
                    }

                    t++;
                }
            }
        }

        // Step 6: Find maximum items within budget
        int answer = 0;

        for (int b = 0; b <= budget; b++) {
            answer = Math.max(answer, dp[b]);
        }

        return answer;
    }
}

```

## **6. Dry Run – Example 2**

```
items = [[2,4],[3,2],[4,1],[6,4],[12,4]]
budget = 8
```

First, calculate the free-item bonus:

| Item | Factor | Price | Free bonus |
| ---- | ------ | ----- | ---------- |
| 0    | 2      | 4     | 3          |
| 1    | 3      | 2     | 2          |
| 2    | 4      | 1     | 1          |
| 3    | 6      | 4     | 1          |
| 4    | 12     | 4     | 0          |

Consider this purchase:

| Item      | Purchased copies | Cost  |
| --------- | ---------------- | ----- |
| 0         | 1                | 4     |
| 1         | 1                | 2     |
| 2         | 2                | 2     |
| **Total** | **4**            | **8** |

Now calculate free items:

- Item 0 generates 3 free items.
- Item 1 generates 2 free items.
- Item 2 generates 1 free item.

Therefore:

\\[ Total = Purchased + Free \\]

\\[ =4+3+2+1 \\]

\\[ \boxed{10} \\]

Output:

```
10
```

## **7. Complexity Analysis**

Let:

- `n` = number of items.
- `B` = budget.
- `M` = maximum factor (1500).

| Operation                | Complexity |
| ------------------------ | ---------- |
| Frequency calculation    | O(n)       |
| Divisibility calculation | O(M log M) |
| DP processing            | O(n × B)   |
| Finding answer           | O(B)       |

**Overall Time Complexity:**

\\[ \boxed{O(M\log M+nB)} \\]

**Space Complexity:**

\\[ \boxed{O(M+B)} \\]

The DP uses two arrays of size `budget + 1`.

## **8. Important concepts to remember**

There are three important concepts in this problem:

1. **Divisibility and Frequency Array:** Instead of checking every pair of items, use multiples to calculate the free-item bonus efficiently.
2. **Unbounded Knapsack:** You can purchase unlimited copies, but only the first copy provides the free-item bonus.
3. **Prefix Maximum Optimization:** Instead of checking every possible number of copies, maintain a running maximum to optimize the DP transition.

**My suggestion:** Pay special attention to the DP transition. The most important idea is that the first copy gives an extra reward, while subsequent copies give only one additional item. This is what makes the problem different from ordinary Unbounded Knapsack.
